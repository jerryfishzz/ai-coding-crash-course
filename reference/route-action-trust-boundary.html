Repo field guide

Before a route action writes

Identify caller → authorize action → validate input → invoke service → rely on DB constraints for invariants
  1. Read the user identity from the request/session; do not trust a user ID supplied in the form.
  2. Check permission on the server for every mutation. UI visibility is presentation, not authorization.
  3. Parse untrusted request data with a runtime schema; static TypeScript types do not validate HTTP input.
  4. Call the service with validated data and handle expected domain/database errors.
  5. Keep constraints in the database as integrity backstops.

Repo example: admin category action. It returns 401 when no user is selected, 403 for a non-admin, and 400 for invalid form data.
