Trace a database write

This time the request creates a durable domain record. We’ll follow one category from the UI to SQLite and separate the form, route, service, and schema responsibilities.

The path

Create category UI → fetcher.submit → route action → admin check + Zod validation → createCategory → Drizzle insert → categories table → action result and refreshed loader data

In CreateCategoryRow, const fetcher = useFetcher() creates a fetcher, and handleSave calls fetcher.submit(..., { method: "post" }). That API call is the code-level reason this is a fetcher submission instead of a normal navigating form submission; React Router handles it as an internal request and leaves the current URL in place. The framework defines fetchers as submitting to actions without navigation—see the official useFetcher action guidance.

You’re right that this code does not tell the browser to navigate afterward. The create branch of the action returns a plain success object (or error data), not redirect(...). The component receives the result in fetcher.data, shows a toast, clears and closes the row; React Router revalidates the route loader so its list data can include the new category.

The route action first reads the current user from the session and checks for an admin role. Then it reads request.formData() and validates it with parseFormData against a Zod discriminated union. The intent chooses which operation to run. For create, the route calls createCategory(name) and returns a success message; it does not build the SQL itself.

In categoryService.ts, createCategory derives a slug, checks for an existing name or slug, then runs db.insert(categories).values({ name, slug }).returning().get(). Drizzle translates that typed operation into an insert and returns the created row. The official Drizzle insert guide covers this query shape.

The schema in app/db/schema.ts declares the categories table; its initial SQL migration adds a unique index on slug. That uniqueness constraint is enforced by SQLite, in addition to the service’s friendly pre-check.

Important distinction: creating a category inserts a row into an existing table. A migration changes the table structure or its constraints. This operation needs a database write, but no new migration.

Quick recall
