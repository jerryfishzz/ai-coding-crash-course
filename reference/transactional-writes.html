Multi-write transaction checklist

One business operation → related SQL statements → one commit/rollback decision
  1. List every row written for the user operation.
  2. Ask whether a partial result is valid. If not, group the database writes in one transaction.
  3. Pass the same transaction handle to every query; a global db query may escape the transaction.
  4. Test success: every expected row exists.
  5. Test failure after an earlier write: the operation fails and no partial rows remain.
  6. Keep external side effects (email, payment provider, HTTP calls) conceptually separate; database rollback cannot undo them.
