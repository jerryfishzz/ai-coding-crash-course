A loader is not a write guard

A loader decides what to show for a page request. An action handles a separate mutation request. Rules needed to protect a write must be checked in the action too.

Compare the purchase route’s two paths

In courses.$slug.purchase.tsx, the loader finds the course and returns 404 if it is not published. It then handles login/enrollment redirects and prepares the purchase page.

The action is invoked separately when the confirmation form is submitted. It parses the course slug, finds the course, checks login, validates the intent, and calculates the price on the server. In the current code, it does not repeat the published-status check before creating the purchase/enrollment.

GET page → loader checks: course exists + Published
POST confirmation → action checks: course exists + logged in + valid intent
Question: does the action enforce every business rule needed before it writes?

Why this matters

The normal UI won’t show a confirmation page for a draft course. But a route action is still a server entry point: a client can submit a crafted POST directly without first following the normal page flow. The loader’s earlier 404 does not run as a prerequisite to every action request. React Router treats loaders and actions as distinct route handlers; see the official actions guide.

For a published-only purchase rule, the action should enforce that invariant itself before inserting anything. This is a code-review finding to verify against the product requirement—not a change made by this lesson. Notice one good pattern nearby: the action recalculates the regional price on the server rather than trusting a price submitted by the browser.

Protect the operation where it happens. A page-level loader can improve navigation and user experience; it cannot be the only guard for a server-side write.

Quick recall

If the loader rejects draft courses, what still needs to enforce “only published courses can be purchased”?

Practice

Assume the product rule is “only published courses can be purchased.” In the current route, where is that rule checked, and what check is missing from the action? Sketch one test using a draft course that proves the action creates neither a purchase nor an enrollment.
