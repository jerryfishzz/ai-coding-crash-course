Route actions are trust boundaries

A form is a convenient way to send a request, not a security boundary. The server must validate each request and decide whether its user may perform the operation.

Trace the category action

Browser form → POST → action: identify user → authorize admin → parse/validate input → service → database

In admin.categories.tsx, the action first calls getCurrentUserId, then loads that user and checks for UserRole.Admin. Only after those checks does it read and validate the form data with parseFormData. It then dispatches the validated intent to the category service.

These checks answer separate questions:

  • Authentication: who is making this request? No current user gets a 401 response.
  • Authorization: may this user manage categories? A missing user record or non-admin role gets a 403 response.
  • Validation: is the submitted intent and data well-formed? Invalid form data gets a 400 response.

Why the order and server location matter

A caller can send a POST without clicking your UI, so hiding an admin button or disabling a form is not authorization. The route action must enforce permission on every mutation. The UI may still hide controls for a clear experience, but the server is authoritative.

Validation is also runtime work: TypeScript types do not validate untrusted form strings. Here Zod checks the discriminated intent and its fields before the service is called. The action export is the server-side mutation handler in React Router’s framework model.

Client-action nuance: a route may also export clientAction. For a submission handled by the hydrated browser router, that client function takes priority; it does not automatically run both functions. If it needs the route’s server mutation, it can call the provided serverAction() helper. A direct HTTP POST to the route (such as a non-JavaScript form submission) is handled by the server-side action. This route exports no clientAction, so its browser submissions use the server action.

Before any write: identify the user, authorize the operation, validate the request, then call the service. Keep database constraints as a final integrity guard.
