Test database rules safely

Arrange related rows → perform the service operation → assert both the error/result and the persisted state
  1. Use createTestDb() from app/test/setup.ts; it opens an SQLite :memory: database.
  2. Keep tests realistic: this helper enables foreign keys and applies the actual drizzle/ migrations.
  3. Set up the exact dependency (for module deletion, create a lesson-progress row).
  4. Call the service and assert the contract: expected error or success.
  5. Query the test database to assert what remains. Do not infer persisted state from the thrown error alone.

A blocked deletion should leave its parent and children intact. A future archive test should prove rows remain but ordinary listings hide the archived module. A cascade test should prove only intended descendants are removed.
