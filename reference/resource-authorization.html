Repo field guide

Authorize the specific resource

Caller → allowed role? → resource exists? → caller may act on it? → nested IDs belong to this parent? → write
  1. Resolve identity from the trusted session, not a submitted user ID.
  2. Check the caller’s broad capability (for example, instructor or admin).
  3. Load the exact resource identified by the route and check ownership/permission.
  4. For nested IDs, verify the child belongs to the authorized parent.
  5. Repeat checks on every loader/action that exposes or mutates the object.
  6. Test with two users and two resources; attempt to substitute the other user’s ID and assert denial with no write.

Repo example: course editor loader and action. Primary source: OWASP IDOR Prevention Cheat Sheet.
