Trace one course page through the app

You already know React components and client/server boundaries. This repo’s useful new move is to follow a page through its server loader and domain services before it reaches the component.

The project is a server-rendered course platform built with React Router, TypeScript, SQLite, and Drizzle. Think of a route module as a vertical slice: it connects a URL, server-side data loading, and the rendered screen.

/courses/:slug → route map → course route loader → course service → SQLite schema → loaderData → React component

Read the flow

In app/routes.ts, the URL pattern courses/:slug points to routes/courses.$slug.tsx. React Router’s loader runs on the server, reads the slug, calls getCourseBySlug, and then gathers related information such as enrollment and progress. The returned object becomes loaderData, which the component uses to render the page.

The service hides query details from the route. courseService.ts composes Drizzle queries over the tables defined in schema.ts. That is similar to keeping a client screen focused on presentation while a separate module owns data access, except this loader is server code and can access the local SQLite database directly. React Router documents the loader-to-component handoff in its data loading guide.

Keep this mental model: route config answers “which module handles this URL?”; the loader answers “what data does this request need?”; services answer “how does this domain query or change data?”
