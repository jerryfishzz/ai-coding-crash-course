Trace a mutation end to end

Let’s follow one real operation—from the React interaction through the route’s security checks, into Drizzle, and back to refreshed UI data.

Example: rename a course module

InlineEditableModuleTitle → fetcher.submit → matched route action → identity + role + course ownership → Zod form parse → module belongs to course? → updateModuleTitle → SQLite modules.title
  1. UI starts it: when the instructor saves, InlineEditableModuleTitle submits { intent: "rename-module", moduleId, title } with fetcher.submit. A fetcher submits without a navigation.
  2. Route establishes permission: the action gets the session user, checks instructor/admin role, parses the course ID from the route, loads the course, and confirms the instructor owns it (admins are allowed).
  3. Route validates and scopes the object: Zod checks the intent, integer module ID, and non-empty title. The action then looks up the module and confirms its courseId matches the authorized route course. A mismatch returns 404 before a write.
  4. Service persists: updateModuleTitle updates the row with that module ID and returns the updated record.
  5. UI catches up: the action returns success; React Router revalidates loader data after actions, so the displayed course/module data can reflect the saved title without a full-page navigation.

References: React Router’s docs for useFetcher and route actions; repo implementation in the course editor route.

Where would you test it?

Service test → does updateModuleTitle write the title?
Route-action test → owner and child-resource guards prevent unauthorized writes?
UI test → does the editor submit and show the refreshed result?

Different tests protect different contracts. The current module service tests already test the service update. A route-action test could arrange two instructors/courses and prove a mismatched module ID returns 404 with no database change. A UI test is useful if the interaction itself is what might regress; it is not a substitute for server authorization tests.

Trace forward to find the write; trace backward to find trust. The service writes the row, but the route is responsible for deciding whether this request may reach that write.
