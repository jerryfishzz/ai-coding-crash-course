Repo field guide

Test resource authorization

A owns A → allow
A targets B's course → 403
A targets own course + B's module ID → 404
Denied request → no persisted change
  1. Create two users with instructor roles and separate courses/modules.
  2. Authenticate each request as the intended user; never pass the user ID as trusted form data.
  3. Test a permitted owner request and verify the intended change.
  4. Test a cross-owner course request and a mismatched child-resource ID.
  5. For every denial, query the isolated database and verify the target row is unchanged.

For this repo, direct action tests should provide a valid cookie session and valid form payload so the request reaches the authorization branch under test.
