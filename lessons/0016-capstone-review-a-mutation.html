Your trace

Use the self-purchase path in courses.$slug.purchase.tsx. Start from the “Confirm Purchase” form, then follow the confirm-purchase intent through the route and services. Don’t change code; this is a code-reading review.

In your own words, answer these six prompts:

  1. What URL receives the form, and what UI mechanism submits it?
  2. What identity, input, and business-rule checks happen in the action before the write? Which published-course guard is missing?
  3. Which service calls write which records, and what does a successful request do next?
  4. If the purchase insert succeeds but enrollment fails today, what partial state may remain? What transaction boundary would protect the invariant?
  5. Name one success-path and one failure-path database assertion that would test the intended behavior.
  6. Which external side effect would not be undone by a database rollback?

Use source links in the route, then cross-check the mutation trace checklist and transaction checklist. React Router’s official actions guide and Drizzle’s transaction guide are the primary references.

One final recall

Where must a rule that protects a database write be enforced?

A dependable trace connects behavior to state. Follow what the user submits, what the server trusts, what the database changes, and what a test proves remains true.
